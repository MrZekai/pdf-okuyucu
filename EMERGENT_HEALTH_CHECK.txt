ANALYZE ONLY — DO NOT WRITE OR MODIFY ANY CODE IN THIS TASK.

Read AGENTS.md first and obey every rule in it. This is an existing
Expo SDK 57 / React Native / TypeScript PDF reader with a deliberate
code style and a 3-language (tr/en/es) i18n layer. I have a very small
credit budget, so this must be a single read-only pass.

Scope of this task:
1. Run the project's own cheap checks and report their output verbatim:
      npm run i18n:check
      npm run typecheck
      npx expo-doctor
   Do NOT run a native build. Do NOT run expo prebuild.
   Do NOT deploy. Do NOT publish. The APK is built for free on GitHub
   Actions, so building here would only waste my credits.

2. Static review, no edits. Report findings grouped as:
   A) BLOCKERS — anything that would fail `expo prebuild` or a Gradle
      Android build, or crash at runtime.
   B) CORRECTNESS RISKS — state/persistence bugs in context/AppContext.tsx
      and lib/storage.ts, file lifecycle bugs in lib/pdfFiles.ts,
      unhandled promise rejections, missing cleanup in hooks.
   C) i18n GAPS — any user-visible string not going through
      constants/i18n.ts, any key present in tr but weak/wrong in en or es,
      any date/number formatting that ignores the active locale.
   D) ANDROID / PLAY READINESS — permissions, AdMob consent (UMP) flow in
      hooks/useAdsBootstrap.ts, whether TestIds vs production IDs are
      wired correctly, anything that would fail Play review.
   E) PERFORMANCE — unnecessary re-renders, large lists without
      virtualisation, PdfView remount cost from its `key` prop.
   F) IMPROVEMENT OPPORTUNITIES — ranked, each with: what, why it matters,
      which exact files it touches, and an estimate of how many files
      would change. Small and reversible first.

3. Hard constraints for your report:
   - Do not propose rewriting the app, changing the framework, replacing
     the PDF engine, adding a backend/auth/database/analytics, or
     upgrading packages just for freshness.
   - Do not propose reformatting the code. The dense one-line JSX plus a
     single StyleSheet.create block per file is intentional.
   - Do not remove `kotlinVersion: '2.3.0'` from app.config.js — it is
     the fix for the play-services-ads Kotlin 2.3 metadata conflict.
   - Cite file paths and line numbers for every finding.
   - If something is fine, say it is fine in one line. No filler.

4. Output format: a single markdown report. No code blocks longer than
   10 lines. End with a section titled "CHEAPEST NEXT STEP" naming the
   ONE task you would do first and the exact files it touches.

Then STOP and wait for me to choose a task.
